### dpy-self Internal Validation

Verified the following against installed dpy-self 2.1.0 source code:

1. `VoiceClient._encrypt_aead_xchacha20_poly1305_rtpsize` -- creates nacl.secret.Aead per call, nonce = 4-byte BE counter + 20 zero bytes, output = header + ciphertext + nonce[:4]. Counter managed via `checked_add('_incr_nonce', 1, 4294967295)`.

2. `VoiceClient._get_voice_packet` -- DAVE encrypt via `dave_session.encrypt_opus(data)` if session ready, then build 12-byte RTP header (0x80, 0x78, seq, ts, ssrc), then transport encrypt.

3. `VoiceConnectionState` instance attributes: `socket` (UDP, SOCK_DGRAM, non-blocking), `dave_session` (Optional[DaveSession]), `dave_protocol_version` (int), `mode` (str), `secret_key` (bytes), `endpoint_ip` (str), `voice_port` (int).

4. `VoiceConnectionState.send_packet(packet)` calls `socket.sendall(packet)`.

5. `VoiceConnectionState.add_socket_listener(callback)` / `remove_socket_listener(callback)` -- registers UDP packet receive callbacks. Used by voice-recv for audio receive.

6. `VoiceConnectionState.reinit_dave_session()` -- creates DaveSession with `(protocol_version, user_id, channel.id)`. For Go Live stream connection, we need a separate DaveSession with the stream's daveChannelId (serverId - 1).

7. Gateway dispatch: `socket_raw_receive` event fires for every gateway message with the raw dict. `socket_event_type` fires with the event name string. Both can be used to intercept STREAM_CREATE and STREAM_SERVER_UPDATE.

### Phase 5 Architecture Summary (from EXECUTIVE_PLAN_V2.md)

Three new modules required:

1. `stream_connection.py` (~250 lines) -- Separate voice WebSocket to stream server. IDENTIFY/READY/SELECT_PROTOCOL/SESSION_DESCRIPTION handshake. Separate DaveSession with daveChannelId = serverId - 1. Heartbeat. DAVE MLS opcode handling (25-31). Speaking mode = 2.

2. `voice_send.py` (~150 lines) -- Extends VoiceClient. Separate video sequence/timestamp/nonce counters. send_video_frame() with DAVE encrypt -> RTP packetize -> transport encrypt -> UDP send. send_audio_frame() reuses existing path.

3. `streamer.py` (~250 lines) -- Main API. join_voice(), start_go_live(), play(), stop(), leave(). Gateway event hooking via socket_raw_receive for STREAM_CREATE/STREAM_SERVER_UPDATE. FFmpeg -> demux -> packetize -> encrypt -> send pipeline.

### Key Technical Decisions Validated

- UDP path (not WebRTC): discord.py provides UDP socket directly
- websockets library for stream WS: independent of dpy-self's curl_cffi
- davey (not dave.py): dpy-self requires davey
- Separate DaveSession for stream: different daveChannelId
- DAVE encrypt before RTP packetize: confirmed from Node.js WebRtcWrapper.ts
- Video needs own seq/ts/nonce: different SSRC from audio

### Open Concerns

- PyAV NUT pipe latency not benchmarked. Fallback: raw Annex-B via `-f h264 pipe:3`
- STREAM_CREATE/STREAM_SERVER_UPDATE dispatch: dpy-self does not handle these natively. Must use `socket_raw_receive` listener.
- davey 0.1.0 vs 0.1.5: version discrepancy. API confirmed identical. May affect DAVE protocol version negotiation.
